可以出方案，但我不建议"一上来全配"这一点，先说理由，再给你一个能直接往下走的版本。

## 判断

混合检索、重排序、查询改写都是有用的候选改动，但它们是"看到对应失败再加"，不是默认配置。"三个都配效果肯定最好"属于经验说法，没有这家客户的评测数据支撑：

- 没有基线，就不知道每一项带来多少、有没有引入偏差（例如查询改写可能把"某型号工序"改偏）。
- 一次全上，后面出了问题无法归因，换解析器、切分、向量模型时也很难重测。
- 制造业制度和工艺规程类问答，限制答案质量的往往不在检索算法，而在文档本身：工艺规程里大量表格（参数、公差、工序卡）、扫描件、多版本并存、ECN/变更后旧版未下线。这些靠加重排序解决不了。

另外还有一个更前置的问题：现有搜索、"目录 + 版本/状态规则"、"规则定位条款 + 原文直出"这些最简方案有没有比过？如果它们在客户认可的验收线上已经够用，应该走更简单的路径，而不是建生成链路。这一步还没做，所以现在不能直接写"建议上完整管线"。

## 一个可以先落地的方案骨架（均为起点，待实测）

| 环节 | 起点 | 什么症状出现才升级 |
|---|---|---|
| 摸底 | 先对客户真实制度和工艺规程做抽样解析，按类型（制度/工艺规程）和格式（原生 PDF、扫描件、Word、Excel）分层，报通过率区间，不只报一个百分比；"解析器没报错"不算通过 | 表格类失败多 → 表格专用解析；扫描件多 → 文字识别（先确认能否出客户环境） |
| 切分 | 按标题/条款/工序边界切，保留章节路径进元数据 | 失败样例的出处被截在两片 → 加重叠或调边界 |
| 检索 | 先跑一版基线（向量或关键词其一）；同时跑最简方案作为对照臂 | 编号、型号、物料号找不到 → 加关键词检索做混合，再看是否需要重排序；用户口语与文档用词不一致 → 术语表，再考虑查询改写 |
| 生成 | 只依据材料、不足则拒答，必须带引用 | 评测里出现无依据陈述 → 再收紧约束 |
| 呈现 | 工艺参数、限值、安全相关条款走"原文优先"，原文卡片带版本、生效日期、状态、章节页码 | 由客户业务负责人按错误代价定哪些问题走此档 |

升级的依据是：同一批题、同一评测集上，最简方案或上一版管线在某一层的失败。型号、物料号这类精确匹配在制造业很常见，所以混合检索很可能最终会加上，但是否加、加多少，应由基线失败来触发，而不是预先配齐。

## 验收怎么定

查制度、规程的问答不是一步，建议按四层验收：①找到候选文件；②核验版本、现行/废止与适用范围（产品型号、工序、产线）；③拿到有权限的正文并定位到条款/页码；④解释适用条件。每类问题要求验收到哪一层，由客户业务负责人定，不是默认都要④。前三层没过，不能说"已正确回答"；有依据地拒答是安全的，但不算任务完成。

## 我最需要你补的三件事（答案会改变结论）

1. **能不能拿到一批真实文档做抽样？** 客户说的是"都是标准 PDF"之类吗？请保留客户原话。拿不到真实样本，通过率只能是转述，解析侧的预算和首批范围都定不了。
2. **谁能给出"最常被问的 10–20 个问题"，并认可怎样算"解决"？** 如果现场只需要"找到那份规程、看到原文"，那么到②③层就够，最简方案很可能已经够用；如果必须"解释适用条件"，才轮到生成起作用。
3. **权限/密级，以及解析、向量化能否出客户环境？** 工艺规程常有保密分级，文字识别和向量化可能不允许外送。这个答案来自客户的安全合规，我不能替他们推定。

还有两个我暂时回答不了、也不替客户回答的问题：同一份规程多版本并存时"以哪一版为准"，以及谁是制度类和工艺类文档的 Owner。这两项需要客户有权限的人确认，否则版本冲突会直接变成错误答案。

## 当前建议结论

**Investigate。** 原因：还没有真实文档抽样，没有问题清单和验收线，没有对照过最简方案，权限和环境未清。这不是"不做"，而是先做最小验证：抽样摸底、10–20 个真实问题、跑一次最简方案对照。这三项做完，我可以把上面的骨架补成完整的知识库判断卡（治理、评测集、各环节升级条件）。

如果你们已经确定要先交付一个原型，我建议原型就按上面的骨架来：基线先行，混合检索、重排序、查询改写作为"待触发"的候选，而不是一开始都配上。你把这三个问题的答案发来，我接着往下展开。

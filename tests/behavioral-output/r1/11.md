这个做法值得做，思路是对的：用户不用先回忆自己知道什么、再比对生成内容和出处，只需要读一段原文。下面按“原文兜底”设计。先说一个前提：它**暴露错误，不消除错误**。检索错了、版本错了，用户看到的就是错的或废止的原文。所以设计重点是别让原文并置变成“看起来有出处”的假安全感。

## 一、先分三档，不是所有问题都“答案 + 原文”

| 档 | 何时 | 呈现 |
|---|---|---|
| A 默认 | 一般问答 | 生成答案 + 出处原文卡片并置（可折叠，可展开前后文） |
| B 原文优先 | 条款、金额、合规、法律、安全等错了代价高的问题 | 先给原文，生成内容只作摘要；或只给检索结果、不生成 |
| C 无依据 | 检索没有合格结果 | 拒答；可附“相关度最高的材料，仅供参考，未找到直接依据”，视觉上要和有依据的回答明显区分 |

哪类问题走 B，由客户业务负责人按错误代价定，不按技术难度定。我不替他们划线。

## 二、原文卡片必须带什么

- 文件名
- 版本、生效日期、状态（现行/废止）
- 责任部门
- 章节或页码
- 命中的原文片段，命中句高亮
- 一键展开前后文（防切分截断，卡片只有半截）
- 打开原件的入口，以及原件页面预览（防解析失败时卡片是乱码或表格错位）

**版本、日期、状态标签必须随原文一起展示，不能省。**这是整套设计最关键的一条。否则用户读到的可能是一段措辞完全正确、但已经废止的原文，还会因为“有原文”而更放心。

## 三、几个会让这个做法失效的地方，设计时要提前堵

| 风险 | 对策 |
|---|---|
| 检索错了或版本错了，用户看到废止版本 | 废止文档默认不检索；同一问题命中多个版本时并列显示并提示冲突，不替用户选。“以哪一版为准”必须由客户有权限的人定 |
| 权限：展示原文等于把文档内容给用户 | 先按用户权限过滤再展示；导出、复制策略由客户安全部门定。这件事在摸底阶段就要问，不能等做完再补 |
| 阅读负担：长段落反而增加成本 | 折叠，只显示最相关的 1 到 3 段，高亮命中句 |
| 用户根本不看原文：并置不等于被核验 | 在答案旁强制显示来源和日期；上线后观察展开率、反馈率（这是假设，待测，不预设阈值） |
| 生成的“解释”部分原文兜不住 | 见下一节 |

## 四、它能保住哪几层，保不住哪几层

按四层任务看（找到文件 → 核验版本/状态/范围 → 取得正文并定位 → 解释适用条件）：

- 原文兜底主要保住第 ②③ 层：状态、范围标签和正文定位，用户看得见。
- 第 ④ 层（解释适用条件）仍可能出错。原文是对的，生成的“这条适用于你的情况”可能是错的。条款类问题的解释部分建议标注“解释供参考，以原文为准”，适用范围由责任人核验。
- 第 ① 层没找对文件，兜底也救不了。用户只会看到一段无关的原文。

所以不要把它对外说成“有原文就不会错”。

## 五、一个顺带的好处，也是一个提醒

- 好处：用户点“答案与原文不符”，可以直接变成评测集的新样例。但进入评测集前，要由 Owner 认可答案和出处，不能直接当真值。
- 提醒：如果检索准确、生成不稳，可以先只上“检索 + 原文”，延后生成。这本身就是一条**最简替代方案**（规则或检索定位 + 原文直出）。建议把它作为评测里的一条对照臂，和“生成 + 原文”同题、同资料、同验收线比较，按四层分别看。这样才知道生成在哪一层真正增加了价值，主要是 ④，还是其实只增加了成本。

## 六、我目前能给的判断（方案设计，部分）

- **呈现**：三档 + 原文卡片 + 版本状态标签，设计思路成立，可以进原型。
- **路径、知识**：还没有依据。我不知道你们的文档解析是否可靠、版本和状态是否有人维护、用户有哪些权限分级。
- **建议结论**：Investigate。理由是权限与密级未清，没有评测集，也没做最简方案对照。这不是否定这个做法，而是它依赖的前提还没确认。

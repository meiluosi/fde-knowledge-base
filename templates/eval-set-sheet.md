## 构成检查
- [ ] 覆盖各问题类型，数量按真实分布
- [ ] 含应拒答题
- [ ] 含路径判断题（本应走数据查询/实时接口）
- [ ] 含版本敏感题
- [ ] 含口语/指代题
- [ ] 含精确匹配题（编号、型号、人名）
- [ ] 含适用范围题（题名相近但对象/工况/区域/阶段不同）
- [ ] 含“已知文件、要找条款”的题
- [ ] 每题标了适用条件与要求层级
- [ ] 同一批题安排了最简方案对照臂（[simplest-alternative.md](../references/simplest-alternative.md)）
- [ ] 每题标准出处都能在库里定位
- [ ] 留出集已封存，不用于调参

## 四层标注记录（供 `scripts/layer_report.py`）
CSV 列：`id,type,required,l1,l2,l3,l4,refusal,should_refuse`。l1–l4 填 1/0，空表示未评；`refusal` 空=正常作答，`safe`=有依据的拒答（库内有出处但依规拒答，如版本冲突未裁定），`wrong`=该答却拒答；`should_refuse` 填 1 表示这是应拒答题（库内无出处），应拒答题单独报“拒答正确”，不进完成率的分母。示例：`Q01,条款查询,4,1,1,1,0,,`；应拒答题：`Q09,应拒答,1,,,,,safe,1`。

## 检索侧标注记录（供 `scripts/retrieval_metrics.py`）
每行一个 JSON：`{"id": "Q01", "type": "条款查询", "gold": ["制度A_v2024#3.2"], "retrieved": ["制度A_v2019#3.2", "制度A_v2024#3.2"]}`
应拒答题 `gold` 写空列表 `[]`。出处标识的粒度（文档/片段）在整个评测里保持一致。

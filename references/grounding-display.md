# 原文兜底：直接给用户看出处原文

来源：用户补充的建议。出发点是降低用户的认知成本：用户不必判断“记忆里的内容”与“生成的答案”是否一致，直接看原文，就能核验。

## 为什么有用
用户核验一条生成答案，要先回忆自己知道什么，再比对生成内容和出处是否一致。把原文与答案并置，核验就变成“读一段原文”。它还有三个附带好处：
- 生成侧的编造风险大幅降低，因为用户看得到依据；
- 用户的“答案与原文不符”反馈直接成为评测集的新样例（见 [eval-set.md](eval-set.md)）；
- 在检索准确、生成不稳的阶段，可以先只上“检索 + 原文”，延后生成。

## 三档呈现

| 档 | 何时 | 呈现 |
|---|---|---|
| A 默认 | 一般问答 | 生成答案 + 出处原文卡片并置（可折叠、可展开前后文） |
| B 原文优先 | 条款、金额、合规、法律、安全等错误代价高的问题 | 先给原文，生成内容仅作摘要；或只给检索结果，不生成 |
| C 无依据 | 检索无合格结果 | 拒答；可附“相关度最高的材料，仅供参考，未找到直接依据”，须与有依据的回答在视觉上区分 |

哪类问题走 B，按错误代价由客户业务负责人定，不按技术难度定。

原文兜底主要保住第②③层（状态、范围、正文定位，见 [task-layers.md](task-layers.md)）；第④层的解释仍可能出错，条款类问题的解释部分应标明“解释供参考，以原文为准”，适用范围由责任人核验。

## 原文卡片必备信息
文件名；版本、生效日期、状态（现行/废止）；责任部门；章节或页码；命中的原文片段（高亮命中部分）；展开前后文；打开原件的入口。

## 它不解决什么（局限与对策）

| 局限 | 说明 | 对策 |
|---|---|---|
| 检索错了或版本错了 | 兜底把错误暴露出来，不是消除；用户可能看到废止版本 | 版本、日期、状态标签必须随原文展示；废止文档默认不检索；冲突时并列显示并提示 |
| 解析失败 | 原文卡片本身是乱码或表格错位 | 提供原件页面预览与页码；解析失败的文档在摸底阶段就应发现 |
| 切分截断 | 卡片只有半截 | 一键展开前后文 |
| 权限 | 展示原文等同于把文档内容给用户 | 按用户权限过滤后再展示；导出、复制策略由客户安全部门定 |
| 阅读负担 | 长段落反而增加成本 | 折叠、高亮命中句、只显示最相关的 1–3 段 |
| 用户不看原文 | 并置不等于被核验 | 在答案旁强制显示来源与日期；用点击率、反馈率观察（假设，待测） |

## 可观察信号（假设，待测，不预设阈值）
原文展开率；“答案与原文不符”的反馈率；用户从提问到确认的耗时；B 档问题中用户最终改用线下渠道确认的比例。这些是上线后的观察指标，不是上线条件；纳入 [eval-set.md](eval-set.md) 的复测。

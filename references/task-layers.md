# 四层任务：问答不是一步，验收要分层

承接 fde-problem-framing 的检索类问题诊断（`references/retrieval-framing.md`，版本指纹见 [upstream-sources.json](upstream-sources.json)）：查标准、制度、知识库的任务可以拆成四层，每一层单独验收。前三层缺一，不能跳成“已正确回答条款”。

| 层 | 要做到什么 | 在本 Skill 里对应 |
|---|---|---|
| ① 找到候选文件 | 目标文件在候选里，且排得靠前 | 检索侧召回与排序（[diagnosis-flow.md](diagnosis-flow.md)） |
| ② 核验版本、效力/状态与适用范围 | 现行还是废止；对哪类对象、工况、区域、时点适用 | 知识状况与治理（[knowledge-health.md](knowledge-health.md)）；原文卡片的版本/状态标签 |
| ③ 取得有权限的正文并定位 | 拿到正文、定位到条款与页码，权限正确，跨页有上下文 | 解析、切分、权限（[doc-audit.md](doc-audit.md)、[pipeline.md](pipeline.md)） |
| ④ 在上下文里解释，供人判断 | 说明适用条件与限制，不超出材料 | 生成侧与呈现（[grounding-display.md](grounding-display.md)） |

## 几条规则
- **不跳层**：只有前面各层都通过，才能说达到更高一层。答案“看起来对”但出处版本是废止的，②没过，不算完成。
- **目录命中不是解决问题**：已知文件但找不到条款时，优先做正文定位和工况对照（③④），不要把①的命中当作任务完成。
- **适用范围与效力要单独核**：官方目录只能证明它展示的元数据；页面里有“废止”字样不等于已废止；相近标准不等于替代；发布日期不等于实施日期；“可参照”不能改写成无条件适用；题名相近不能跨行业、对象或阶段套用。这些判断由客户的责任人作出，本 Skill 不作法律或专业结论。
- **安全拒答不等于任务完成**：有依据地拒答是安全的失败模式，值得保留，但业务任务没有完成。评测里单列，不计入“完成”。
- **每类问题要求达到哪一层，由业务验收定**：例如“找到条款并解释适用条件才算解决”就是要求 ④；只想知道有没有这份文件，要求 ① 就够。写进判断卡与评测集，不要默认所有问题都要 ④。
- **分层记录失败**：一道题答错，先看是哪一层首先出问题，再回诊断流程；这与检索侧、生成侧的划分互补（①对应检索侧的召回，②需要治理，③跨解析与切分，④对应生成侧）。

## 与简单方案的关系
最简方案常常能完成 ①②③，生成只在 ④ 增加价值；见 [simplest-alternative.md](simplest-alternative.md)。分层评测让这个判断有数据，而不是凭印象。

## 工具
`scripts/layer_report.py` 对人工逐题标注的层级结果做汇总：每道题达到的最高连续层级、是否达到要求层级、越层标注（后面层通过而前面层未过）、安全拒答与“该答却拒答”单列、完成率区间；应拒答题（库内无出处）单独汇报“拒答正确”，不与完成率混在一个分母里。它只汇总标注，不判断标注是否正确。

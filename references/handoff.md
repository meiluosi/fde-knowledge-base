# 与系列其他 Skill 的衔接

各 Skill 独立运行，通过手动读取的产物衔接，不互相依赖安装，也不修改它们的仓库。没有上游产物也能独立运行，缺的标“未提供”，不模拟导入成功。上游两个公开仓库的版本指纹见 [upstream-sources.json](upstream-sources.json)；其余 Skill 只记录接口。

## 编号命名空间
跨 Skill 引用加前缀，保留原编号：`ramp:S01`、`framing:V2`、`route:C3`、`kb:Q01`。本 Skill 内部：摸底样本 `D#`、知识问题 `K#`、评测题 `Q#`、诊断记录 `F#`。多批输入同名时命名空间化并保存映射，禁止覆盖原编号。

## 输入

| 上游 | 承接什么 | 本 Skill 新增 |
|---|---|---|
| fde-problem-framing 定义卡 | 场景、所针对的环节、成功指标、错误代价、拦截方式 | 把“要回答什么问题”拆成问题类型与路径；错误代价决定原文优先的范围 |
| framing 的验证计划与抽样 | 已有样本、标注与仲裁安排 | 沿用并补“标准出处”字段，变成评测集 |
| framing 的 retrieval-framing 思路 | 区分“找到文件”“核验状态与范围”“回答正文条款” | 对应本 Skill 的检索、治理（状态）、生成三层 |
| fde-route-selection 决策卡 | 路线（含是否检索）、部署形态、硬约束（数据不出境、私有化） | 硬约束约束解析/识别/向量化能否用外部服务；路线选了非检索时只核对冲突 |
| ramp 的 activities、glossary、corrections | 谁在查文档、术语、已修正的流程 | 已校准术语进同义词/术语表；活动表里的“查制度/翻手册”环节是问题来源 |

给输入记录路径、版本/哈希与读取日期。上游的结论是 Non-AI 或路线卡选的不是检索时，不强行推知识库。

## 输出

| 下游 | 交什么 |
|---|---|
| fde-route-selection | 反馈：问题类型分布与不适合检索的比例；摸底发现的环境约束（如识别服务能否出环境）；改道路径是否需要生成查询语句的模型 |
| fde-demo | Demo 用的是精选文档还是随机抽样的真实文档，必须写明；精选 Demo 的成功不能替代摸底；用评测集里的失败样例作为 Demo 的“已知局限” |
| fde-pilot | 评测集与指标定义（检索、生成分开）、治理状态与 Owner、原文兜底的观察指标；知识库更新后的复测安排 |
| fde-comms | 对客户说“这是知识治理问题”的事实依据：冲突清单、过期清单、缺口清单，措辞与策略交 comms 的坏消息、向上汇报模板 |
| fde-problem-framing（回写） | 摸底发现问题定义本身有疑问（如“全部问题”其实多数是数据查询类）时，写成回写建议，不悄悄改定义 |

## 回写规则
下游发现上游假设被推翻，或客户纠正了流程、术语，写成“回写建议”：对象产物、原内容、新证据（带前缀编号）、建议修订。由上游 Skill 的修订流程处理，不直接改原件。

## 系列地图中的位置
本 Skill 位于 problem-framing 之后，与 route-selection 并行或其后：route-selection 决定“用什么手段”，本 Skill 在手段含文档检索时决定“知识够不够、怎么治、怎么评、卡在哪”。边界：模型比选、成本估算、部署约束归 route-selection；业务问题是否成立归 framing；评测的执行与试点归 pilot；对客户的措辞归 comms。

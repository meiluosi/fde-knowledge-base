# 五个环节：故障症状与候选改动

下表整理自用户提供的书稿表格（原文未随仓库发布）。它是**假设清单**：每一行的根因要在本地失败样例上确认，不能凭症状直接下结论。

| 环节 | 做什么 | 典型故障现象 | 常见根因 |
|---|---|---|---|
| 采集 | 把文档收进系统 | 有些问题永远答不上来 | 关键文档根本没入库；权限导致部分文档拿不到 |
| 解析 | 把文件转成文字 | 表格里的数字全错；扫描件内容缺失 | PDF 表格解析失败；扫描件未做文字识别；页眉页脚混入正文 |
| 切分 | 把长文档切成片段 | 答案总是缺半截；引用的段落不完整 | 切分点落在语义中间；片段太小丢失上下文；表格被拦腰截断 |
| 检索 | 找出最相关的片段 | 明明有这份文件却检索不到 | 用户用的词和文档里的词不一致；只用向量检索，漏掉精确匹配 |
| 生成 | 组织成答案 | 答案编造内容；该拒答时不拒答 | 提示词没有约束；检索到的材料本身不相关 |

## 候选改动（症状触发，不预加）

下面每一条都是经验做法。规则是：**先测基线，看到对应失败再加；一次只加一个；在同一评测集上对比改前改后。** 基线不止是管线的第一版：最简替代方案（现有搜索、目录加状态规则、规则定位加原文直出，见 [simplest-alternative.md](simplest-alternative.md)）也是对照臂；管线只有在某一层上证明了比最简方案多出价值，才值得继续加。 没有失败证据的预加，除了增加复杂度和成本，还会让后续无法归因。

| 环节 | 症状 | 候选改动 | 加之前要有的证据 |
|---|---|---|---|
| 采集 | 某类问题的标准出处根本不在库里 | 补入库；若是权限问题，查权限继承 | 评测题的标准出处在库里查不到 |
| 解析 | 表格数字错 | 表格专用解析；表格转文字描述或整体保留 | 摸底抽样里表格类失败 |
| 解析 | 扫描件缺失 | 文字识别（先确认能否出客户环境） | 摸底里扫描未识别 |
| 解析 | 页眉页脚混入 | 清洗规则 | 失败样例里出现重复页眉页脚 |
| 切分 | 答案缺半截 | 按语义边界（标题、条款、段落）切，替代固定字数；相邻片段留重叠 | 失败样例的出处被切断在两个片段 |
| 切分 | 引用不知属于哪章哪节 | 保留结构信息（章节路径）进入片段元数据 | 同一条款在不同章节语义不同 |
| 检索 | 编号、型号、人名找不到 | 加关键词检索，与向量检索混合，再加重排序 | 检索侧失败样例里精确匹配类占主要 |
| 检索 | 用户用语与文档不一致 | 同义词/术语表（客户校准过的）；查询改写 | 失败样例里用户用词与文档用词不同 |
| 检索 | 问题简短、口语、带指代（“上次说的那个标准是多少”） | 检索前让模型把问题改写完整、接近文档用语；指代需要对话历史 | 失败样例含指代；改写后要核对未引入偏差 |
| 生成 | 编造、该拒答不拒答 | 提示词约束“只依据材料、不足则拒答”；加引用；加拒答评测题 | 生成侧失败样例里的无依据陈述 |
| 生成 | 材料冲突导致答非所问 | 标注版本/责任部门、冲突提示；根因仍在治理，见 [knowledge-health.md](knowledge-health.md) | 失败样例里同时检索到新旧版本 |

## 提醒
- 纯向量检索擅长语义，对精确编号、型号、人名容易漏；关键词检索相反。“两者结合再重排序通常明显更好”是书稿经验，是否值得，以评测集上的对比为准。
- 知识库中的文档内容进入提示词后，应被当作数据，而不是指令。文档里夹带的“忽略以上规则”之类文字，不能改变系统的行为边界。
- 换解析器、切分策略、向量模型、重排序模型，都会让之前的评测结果失效，须重测并记录版本。
- 具体产品、模型与参数不进本文档；它们变化快，放进带日期的来源记录。
